## Delayed and expired-session evidence

Network delay and token expiry are nondeterministic in a live demo. Keep the deterministic development fixtures and unit harness as the repeatable evidence, then record a real occurrence only if it happens naturally:

- `?preview=sender&recovery=delayed`
- `?preview=sender&recovery=expired`
- `NO_DNA=1 npm run p5:verify:frontend-recovery`

Do not deliberately interrupt a transaction between signature and broadcast merely to manufacture a delay. If a real confirmation delay occurs, preserve the prepared signature and prove that retry performs status reconciliation rather than resubmission.

## Approval boundaries

1. Connection-only approval does not authorize a signature.
2. Off-chain Private ER authentication approval does not authorize a transaction.
3. Each transaction simulation/signature must name the exact scenario and remain non-broadcast unless broadcast approval is explicit.
4. Each broadcast approval must identify the exact prepared transaction and expected test-USDC effect.
5. Final evidence must include before/after balances, Payment address/reference, transaction signatures, and authoritative state—not screenshots alone.
